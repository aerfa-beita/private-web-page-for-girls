# 完整回忆档案迁移到 Firebase Storage

## 目标

将完整回忆档案从 Vercel 源码中移出，只保留首页 6 张拍立得作为首屏与弱网回退。完整档案、朋友投稿和审核后的照片统一由 Firebase 承载。

## 最终数据边界

| 内容 | 承载位置 | 页面行为 |
| --- | --- | --- |
| 首页 6 张拍立得 | Vercel 静态文件 | 首屏立即显示；Firebase 不可用时仍可打开回忆 |
| 完整回忆档案 | Firebase Storage `archive/` | 打开“所有回忆”后读取 Firestore `archivePhotos` 并按 `sortOrder` 展示 |
| 朋友投稿 | Firebase Storage `carousel-submissions/{uid}/` | 先压缩、限额、待审核，不能直接出现在页面 |
| 已审核朋友照片 | Firestore `carouselPhotos` | 公开读取；审核动作继续由 Firebase Console 完成 |

`image_carousel.js` 不再内置完整图片路径。连接 Firebase 成功后，它会用 `archivePhotos` 中的下载地址替换本地回退池；连接失败时只展示首页 6 张，不会卡住或出现空白轮播。

## 已加入的文件与规则

- `scripts/media/migrate-archive-to-firebase.js`：不依赖第三方包的迁移工具，默认仅预演；必须显式传入 `--execute` 才会上传和写入 Firestore。
- `firebase/firestore.rules`：`archivePhotos` 对访客只读，网页客户端没有写入权。
- `firebase/storage.rules`：`archive/` 对访客只读，网页客户端没有写入权。
- `firebase.json`、`.firebaserc`：将两份规则绑定到 Firebase 项目 `new-univese`。
- `.gitignore`：以后只允许 6 张首屏照片继续进入 Vercel 源码树。

迁移工具为每张图片写入以下字段：`fileName`、`storagePath`、`imageUrl`、`sortOrder`、`source`。图片设置一年不可变缓存；更新图片时应使用新文件名，避免旧缓存干扰。

## 小花先生需要执行的上线顺序

1. 在 Firebase 控制台创建或下载一个服务账号 JSON，放在仓库外的私有位置，绝不能放进仓库。该账号需要具备写入 Storage 与 Firestore 的权限；可使用项目现有的 Firebase Admin 服务账号，或由项目所有者授予最小必要权限。
2. 登录 Firebase CLI 后发布规则：

   ```powershell
   npx firebase-tools@latest deploy --only firestore:rules,storage --project new-univese
   ```

3. 先只核对本地文件清单，不会访问网络也不会修改图片：

   ```powershell
   node scripts/media/migrate-archive-to-firebase.js --dry-run
   ```

4. 再执行正式迁移；`C:\private\new-univese-service-account.json` 只是示例路径：

   ```powershell
   node scripts/media/migrate-archive-to-firebase.js --execute --service-account C:\private\new-univese-service-account.json
   ```

5. 在 Firebase Console 确认 `archivePhotos` 数量与 `archive/` 文件数一致，再打开本地页面的“所有回忆”确认照片正常显示。
6. 迁移验证和 Vercel 预览都通过后，再由小花先生明确授权进行 Git 索引清理：只移除其余完整档案的 Git 跟踪，不删除本地原图，也不动 6 张首页照片。这个步骤必须最后做，因为一旦过早取消跟踪，旧 Vercel 部署仍可能依赖本地文件。

## 安全说明

- `archive/` 是小花先生决定公开展示的共同回忆，读规则为公开；它不是私密文件保险箱。
- 待审核投稿目录仍要求匿名登录且只允许本人删除自己的孤立上传，不会因完整档案迁移而放开。
- 服务账号 JSON、Firebase 私有密钥、天气密钥和测试配置都不进入 Git，也不进入 Vercel 静态文件。
- 工具故障会停止在当前图片；可修复后重跑。文件名对应固定对象路径和固定文档 ID，重复运行会覆盖同名对象与同一条元数据，不会创建第二套轮播记录。

## 验收

- `node --check image_carousel.js`
- `node --check scripts/media/migrate-archive-to-firebase.js`
- `node scripts/media/migrate-archive-to-firebase.js --dry-run`
- `node --test tests/site-features.test.js`
- 发布规则后：匿名访客能读取完整档案；浏览器网页不能写入 `archive/` 或 `archivePhotos`；朋友投稿仍只进入待审核路径。
