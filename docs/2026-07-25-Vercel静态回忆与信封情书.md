# 2026-07-25 Vercel 静态回忆与信封情书

## 目标

保证线上 `love.xiahuaaitalk.top` 的完整回忆不依赖 Firebase：93 张现有照片与现有 MP3 均由 Vercel 静态资源直接提供。Firebase 只保留给日后新增或朋友投稿，服务异常不能让既有档案变黑或退回为六张。

## 实现

- `image_carousel.js` 增加 `STATIC_ARCHIVE_FILES`，列出 `assets/Photograph/IMG_20260228/` 下 93 张可展示 JPG；切换到“档案”时按需加载。
- 静态照片优先于 Firebase；Firebase 不可用时仍使用完整 93 张列表，首页 6 张仅是独立回忆页内容。
- `.gitignore` 保留主目录照片的发布白名单，并忽略 `*_tmp.*` 临时文件，避免把压缩中间文件部署为第 94 张。
- `sw.js` 使用 `our-universe-v65-static-memory-archive`，同时把轮播脚本升级为 `image_carousel.js?v=4`，避免旧缓存继续执行 Firebase 优先的版本。
- 音乐播放器增加一次性接管标记：首次允许播放的手势固定播放《如果这份爱》，缓冲期间不会被随机队列抢换；手动“下一首”或播放结束后才从其余歌曲随机选择。
- 月亮长按后由 `love_letter.js` 先打开信封；点击信封，才翻开信纸并逐字展示原有月亮信件。没有新建第二套文案来源。
- 地球页将心动轨迹左移、永恒之约上移，并为展开文案留出距离；“此刻”双模块下移居中；每日一句加宽加大。

## 发布后验收

1. 打开真实域名，解锁后进入左侧“档案”，确认计数为 `1 / 93`，连续切换、自动播放与返回都不会退回六张。
2. 关闭网络后重新进入已打开的档案，确认已缓存照片仍能显示；网络正常时随机抽查前、中、后各一张照片的路径可打开。
3. 从开场长按月亮，确认先出现信封；点击信封后才升起信纸和文字。
4. 刷新真实域名，确认 Service Worker 已更新到当前版本，背景、照片、8 首 MP3 和默认开场均能正常加载。

## 边界

- 这次不执行 Firebase 迁移、不删除照片、不清理留言。
- Firebase Storage 规则和朋友投稿验收继续独立进行，不能作为完整回忆档案的前置条件。
