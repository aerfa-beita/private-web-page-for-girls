# 2026-07-22 记忆档案与此刻页面重构

## 本次结论

- 公开页面不再展示留言板、留言失败提示或“功能不可用”提示；现有 Firestore 留言数据保留，未作删除。
- 留言功能只保留给本地内部测试。只有本机私有 `config.js` 显式设置 `ENABLE_MESSAGE_TESTING: true` 时，测试面板才会出现；该配置默认关闭且不得提交到 GitHub。
- 正式交付前的留言清理是一次独立、不可逆的发布步骤，必须在小花先生再次确认后才执行。
- 首页只展示固定的三张拍立得照片；“展开所有回忆”后才加载完整回忆档案，避免首页与照片展示区重复。
- 原“秘密基地”改为“此刻”：桌面端为并列的同频心跳与天气卡片，移动端自然改为单列。两位不同访客同时在线时显示粒子心形；单人在线时只显示安静的单点。

## 留言数据与正式发布

### 当前测试方式

在本地私有 `config.js` 中加入下面一项，可临时打开留言测试面板：

```js
ENABLE_MESSAGE_TESTING: true
```

测试结束后删除该项或改为 `false`。线上公开版本不应包含这项开关，因此访客看不到留言入口、历史留言或失败状态。

### 正式交付前的清理清单

1. 小花先生先确认不再需要当前测试留言，并决定是否先导出或截图留存。
2. 在 Firebase 控制台确认目标项目与 `messages` 集合无误。
3. 仅在小花先生明确同意后，删除 `messages` 集合中的测试文档。
4. 再次确认生产配置中没有 `ENABLE_MESSAGE_TESTING: true`，并用无痕窗口检查公开页面。

本次没有执行第 3 步，也没有接触任何现有 Firestore 留言。

## 回忆照片与朋友投稿

- 自有照片与音乐仍随 GitHub 推送进入 Vercel 的静态部署；它们不需要 Firebase Storage。
- 朋友投稿走 Firebase Storage：浏览器先限制格式、15 MB 原文件、压缩为不大于 1 MB 的 JPEG，再上传到 `carousel-submissions/`；Firestore 记录为 `pending`，只有审核后手动写入 `carouselPhotos` 的照片才会向所有访客展示。
- 已提供本地规则文件 `firebase/firestore.rules` 与 `firebase/storage.rules`，分别覆盖投稿限额、待审核记录和 Storage 路径限制。规则尚未在 Firebase 控制台发布，发布及真实设备验证前，不把投稿功能视为线上完成。

## 上线前仍需人工验收

1. 在 Firebase 控制台发布本项目的 Firestore 与 Storage 规则。
2. 用两个不同浏览器或设备检查“此刻”的在线心形；确认 Realtime Database 规则允许匿名状态写入。
3. 以朋友身份提交一张测试图，确认它保持“待审核”，审核后才进入公开档案。
4. 推送前只暂存需要发布的代码和压缩后的静态媒体；不要使用 `git add .`，以免带入私有配置、原始备份或临时图片。
5. Vercel 部署完成后，在真实域名重新检查照片、音乐、弱网降级和缓存更新。
