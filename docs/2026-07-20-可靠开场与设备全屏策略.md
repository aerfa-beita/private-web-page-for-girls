# 2026-07-20 可靠开场与设备全屏策略

## 背景

线上复现显示：刷新后 3 秒没有 WebGL 画布，16 秒后进入静态备用开场。原实现依赖单一 Three.js CDN，且全局 15 秒兜底会与正在加载的动画竞争；备用开场只在 Three.js 成功创建场景后才能随主页卸载。

## 开场修复

- 开场先于 Firebase SDK 加载启动，避免 Firebase 网络慢阻塞开场。
- Three.js 优先读取 `assets/vendor/three.r128.min.js`，外部 CDN 仅作为后备。
- 单个资源在 4.5 秒无响应即进入静态开场，不再使用与动画时长耦合的 15 秒全局计时器。
- 无论 Three.js 是否成功，进入主页后都会卸载 `#opening-fallback`，不会在密码正确后残留静态狮子。
- `lion_background.js` 缓存查询版本升至 `v=22`，Service Worker 缓存升至 `our-universe-v25-reliable-opening`。

## 设备策略

| 设备 | 自动全屏 | 方向 |
| --- | --- | --- |
| 手机 | 否 | 不锁定；以竖屏窄版为默认布局 |
| 平板 | 否 | 不锁定；以竖屏阅读为主，横屏仅自适应 |
| 桌面端（至少 900px、精确鼠标） | 是 | 使用浏览器全屏 |

浏览器显示的“已进入全屏模式”属于浏览器原生安全提示，网页不能移除；仅桌面端会触发它。

## 验证

- `node --test tests/site-features.test.js`：17 项通过。
- 仍需将 Three.js 本地文件放入 `assets/vendor/` 后，在真实桌面和手机设备上验收动画与静态降级。
