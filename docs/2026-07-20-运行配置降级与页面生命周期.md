## 新增运行配置模块

新增 `scripts/services/runtime-config.js`，它只读取 `firebase-config.js` / 本地 `config.js` 已提供的 `window.__CONFIG__`，并公开一个只读的 `window.UniverseRuntimeConfig`：

- `hasFirebase`：仅当 `apiKey`、`authDomain`、`projectId`、`appId` 都存在时为真。
- `hasWeather`：仅当天气 Key 非空时为真。
- `firebaseConfig` 和 `weatherApiKey`：供页面业务逻辑读取。

这是一层很小的服务边界。页面不再直接猜测空对象是否可初始化，后续 Firebase、天气和 Cyber-me 可以继续分别迁移到 `scripts/services/`。

### 页面降级行为

- Firebase 未配置：不初始化在线心跳；秘密基地显示“留言服务尚未配置”，不会再抛出初始化错误或给出错误的重连按钮。
- Firebase 已配置但 CDN 仍在加载：在线心跳和秘密基地都等 `firebaseReadyPromise` 完成后再初始化，避免先解锁页面时把“暂未加载”误判成永久不可用。
- 天气 Key 未配置：不向 OpenWeatherMap 发送 `appid=` 空请求；两张天气卡明确提示服务未配置，其他内容继续可用。
- 此改动不把天气 Key 视作安全方案。公开上线前仍应改为同源服务端代理。

## 回忆放映机按需初始化

`image_carousel.js` 现在提供幂等的 `window.initImageCarousel()`：

- 首次 `switchModule('image-carousel')` 后创建轮播 DOM、绑定事件并启动自动轮播。
- 重复切换不会重复注入样式、重复绑定事件或重复启动计时器。
- 如果用户在外部脚本尚未加载完成时已经切换到该页面，外部脚本加载后会检查当前激活状态并只补做这一次初始化。

这让隐藏模块在首屏不再做无效渲染和后台定时工作。

## 生日花瓣生命周期

`closeBirthdayModal()` 统一处理关闭逻辑：

- 取消当前动画帧并清空动画 ID；
- 移除唯一保存的窗口 `resize` 回调；
- 清空回调引用，下一次打开时再安全创建。

因此同一页面多次打开生日祝福，不会累积窗口监听器。
