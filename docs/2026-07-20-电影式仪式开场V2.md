# 2026-07-20 电影式仪式开场 V2

## 目标

将旧的“两次按钮 + Three.js 狮子座”开场替换为一条连续的私人仪式：用户不是点击进入网页，而是亲手点亮第一颗星，再看见银河与从星点显影的狮子座、输入只有两人知道的数字，最后让银河收拢为主页。

本次改动只位于 `.worktrees/modular-opening`，主目录未改动。

## 开场节奏

| 阶段 | 时长 | 页面与交互 |
|---|---:|---|
| 黑幕与字幕 | 0–12.5 秒 | `#050510`、微弱颗粒呼吸、三段居中字幕；无按钮、无首页 UI。 |
| 第一颗星 | 12.5 秒后 | 只显示一颗带金色光晕的恒星与“轻轻点一下”。 |
| 点亮世界 | 用户点击后 0–7 秒 | 星体心跳、三圈光波、背景音乐渐入、星点分批出现。 |
| 银河、狮子座与情绪文案 | 点击后 7–15 秒 | 银河螺旋显现，透明狮子座线稿从星点里显影，依次出现“谢谢你”与“送你一片星空”。 |
| 星点密码 | 点击后约 15 秒 | 四颗或更多密码星点随输入逐颗点亮；错误时星点轻颤。 |
| 进入主页 | 密码正确后 1.1 秒 | 银河缩小收拢，开场淡出，主页 Hero 自然出现。 |

总时长由用户点亮星星的时间决定；按照首次看到星星后约两三秒点击，整体约 28–35 秒。

## 模块拆分

### `scripts/opening/cinematic-opening.js`

只管理电影开场的视觉状态和时间轴：字幕、第一颗星、光波、星空、银河、透明狮子座显影、回到密码阶段、收拢到主页。它不读取 Firebase、不校验密码、不直接操作业务模块。

### `scripts/opening/opening-flow.js`

只负责在 `cinematicPasswordRequested` 时显示密码层、从密码层返回星光，以及密码正确后调用银河收拢。它不绘制星星。

### `index.html`

仍保留密码校验和进入主页后的业务初始化；密码输入改为真实但视觉隐藏的数字输入框，`#pin-stars` 仅负责显示输入进度。密码长度仍从 `SECRET_CODE` 自动读取，代码不限定四位。

## 设计与性能边界

- 新开场不依赖 Three.js 或 CDN；狮子座使用仓库内的透明线稿 `assets/Leo/leo-linework-transparent.png?v=15`，弱网和手机都走相同视觉路径。
- 星点仅在启动时创建一次；动画只改变 `transform`、`opacity` 与 `filter`。
- 新开场统一使用 `cubic-bezier(.22,.61,.36,1)`，没有为该模块新增 `ease` 或 `linear` 动画。
- 背景音乐只在点击第一颗星的真实用户手势中启动；本轮没有新增独立环境音资源。
- 旧的 `lion_background.js` 保留在 worktree，供静观页历史功能和素材参考，但不再由首屏加载。

## 回退与返回

`opening-flow.js` 缺失时，页面仍直接显示密码层，避免用户被困在黑屏。密码层点击“回到星光里”后，银河会停留在密码阶段；再次点中心星可重新打开密码星点。
