# 2026-07-20 本地预览缓存与编码修复

## 现象

本地地址 `http://127.0.0.1:5173/` 显示深色背景和乱码文字，看不到开场互动。

截图中的文字实际是 Service Worker 的离线兜底文案“📱 当前离线，请连接网络后重试”，并非页面主内容。

## 根因

1. `sw.js` 的离线 `Response` 仅声明 `text/html`，没有声明 UTF-8；浏览器在离线时可能按错误字符集解码中文和 emoji。
2. Service Worker 的作用域按“协议 + 域名 + 端口”划分。不同 worktree 若都使用 `127.0.0.1:5173`，会共享旧 Service Worker 和缓存，导致新 worktree 被旧缓存或离线兜底页覆盖。
3. 原本的本地服务器固定端口且没有启动提示；端口被占用或终端服务停止时，浏览器会直接落入旧 Service Worker 的离线页面。

## 修复

- `sw.js` 的离线页响应改为 `Content-Type: text/html; charset=utf-8`。
- `index.html` 在 `127.0.0.1` 或 `localhost` 本地预览时不注册 Service Worker，并注销同源已有注册。
- `serve-local.js` 支持端口参数，所有本地响应加 `Cache-Control: no-store`，并打印实际访问地址或端口错误。

## 固定预览方式

在新 worktree 运行：

```powershell
cd D:\MY_Project\web-page\.worktrees\modular-opening
node serve-local.js 5174
```

保持该终端运行，再打开：`http://127.0.0.1:5174/`。

端口 `5174` 与旧的 `5173` Service Worker 作用域隔离；本地预览不启用 PWA 缓存，线上部署仍保留 Service Worker。

## 验证

- 本地服务器：HTTP 200、`text/html; charset=utf-8`、`Cache-Control: no-store`、页面包含当前开场节点 `cinematic-origin-star`。
- `node --check scripts/opening/opening-flow.js`
- `node --check lion_background.js`
- `node --check serve-local.js`
- `node --test tests/site-features.test.js`

结果：18/18 通过。
