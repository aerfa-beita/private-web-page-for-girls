# 月亮长按情书流程修复

日期：2026-07-26
范围：GitHub `main` 对应的主工作区月亮情书交互。

## 目标

固定并隔离以下流程：

```text
长按月亮 1.2 秒
  → 每日一句话弹窗
  → 点击“收下这句话”
  → 宇宙信封出现
  → 点击封蜡按钮
  → 上盖翻转，信纸升起并开始打字
```

遮罩点击与 `Esc` 只关闭每日一句，不再误进入信封。

## 实现

- `lion_background.js` 继续只负责长按进度与派发 `loveLetterRequested`，避免把弹窗与信封逻辑耦合进 Three.js 场景。
- `love_letter.js` 将“收下”与“关闭”拆分：只有 `data-accept-letter` 会在 260ms 后调用 `showEnvelope()`；异步获取的旧句子以请求编号失效，不能覆盖后一次打开。
- `components/cosmic-envelope/envelope.js` 在加载后派发 `cosmicEnvelopeReady`，覆盖组件脚本较晚可用的边界；关闭信封时清理信纸延迟计时器和逐字计时器，避免下一次打开串入旧内容。
- 封蜡由 `div` 改为有 `aria-label` 的原生 `button`，鼠标、触摸、键盘均可打开信纸；信纸逐字写入改用 `textContent`。
- 静态资源版本更新为 `love_letter.js?v=2`、信封 CSS/JS `?v=8`，Service Worker 缓存更新为 `our-universe-v68-moon-letter-flow`。

## 发布后人工验收

1. 在桌面与手机各完成一次月亮 1.2 秒长按，确认仅出现每日一句。
2. 点击“收下这句话”，确认出现未打开的信封；点击遮罩或按 `Esc` 时不应出现信封。
3. 点击封蜡，确认 0.6 秒后上盖翻转、信纸升起并开始逐字显示。
4. 在信纸尚未开始打字时关闭信封，再次走完整流程，确认不会出现旧信内容或提前打字。
