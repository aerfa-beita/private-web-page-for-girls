# Firebase 心跳与弱网降级修复

> 日期：2026-07-22

## 背景

2026-07-21 的部署准备改动完成了基础降级界面，但在线心跳、月亮信件和弱网加载仍有边界问题。本次只修复运行可靠性，不包含留言图片上传界面。

## 修复内容

### 1. 在线心跳不会误删仍在线访客

- 旧实现仅在连接成功时写一次时间戳，却在两分钟后由任意页面清理过期记录。
- 新结构为 `status/{browserId}/{tabId}`：浏览器 ID 存于 `localStorage`，标签 ID 存于 `sessionStorage`。
- 每个标签页独立注册 `onDisconnect()`；关闭一个标签不会删除同浏览器其他标签的记录。
- 使用 Realtime Database 的 `ServerValue.TIMESTAMP`，每 45 秒续期一次；三分钟内存在任一活动标签即算该浏览器在线。
- 页面只过滤过期记录，不再由客户端删除其他访客的数据，避免活跃用户被误删。
- 读取逻辑兼容旧版 `status/{visitorId}: { ts }` 数据，发布后无需迁移。

### 2. 月亮信件固定回退到站内预设

- `/api/config` 的空 `MOON_LETTERS` 不再覆盖 `LOVE_QUOTES`。
- 月亮长按先读取有效的专属情书；为空或未配置时必定使用 `LOVE_QUOTES`。
- 移除了月亮彩蛋对 Hitokoto 的网络依赖，弱网下也会立即显示站内文案。

### 3. 远程配置不再阻塞开场

- 密码继续优先读取本地 `config.js`，线上缺失时固定使用 `0729`。
- `/api/config` 改为异步请求，八秒后自动放弃；它只提供天气 Key 和可选的专属情书，不再返回密码。
- 远程配置晚到时会刷新天气模块；失败时页面保持可用并显示未配置状态。
- Service Worker 排除 `/api/`，避免旧的环境变量响应进入 CacheFirst 缓存。
- 缓存版本升级为 `our-universe-v40-firebase-resilience`，让已访问过页面的设备更新此规则。
- `.gitignore` 明确反向包含 `api/config.js`：原有无路径的 `config.js` 规则会误忽略该 Vercel Function，导致接口不会随 Git 部署。

### 4. Firebase 与天气弱网超时

- Firebase SDK 加载上限为 12 秒；超时后留言和心跳显示可理解的降级状态。
- 若 SDK 随后加载成功，会派发 `firebaseSdkReady` 并自动重新初始化在线心跳和秘密基地。
- 天气请求每座城市独立设置 8 秒超时；任一城市失败只显示该城市“暂时无法获取”。
- 天气加载不再等待 Firebase SDK，因此 Firebase CDN 不稳定不会拖住天气卡片。

## 配置与验收

- Vercel 必填：`WEATHER_API_KEY`。
- Vercel 可选：`MOON_LETTERS`，格式为 JSON 字符串数组，例如 `["第一封信","第二封信"]`。
- `SECRET_CODE` 不需要再设置为 Vercel 环境变量；线上默认值为 `0729`。
- Firebase Realtime Database 规则需允许当前站点写入 `status/{browserId}/{tabId}` 并监听 `status`；发布后用两个浏览器分别停留超过三分钟，确认两端仍显示“也有人在这片星空里”。
- Firebase Storage 已升级到 Blaze；图片上传仍是独立功能，后续需实现文件校验、压缩、Storage 规则、上传与留言关联。
